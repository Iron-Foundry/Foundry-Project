Verdict & relevance

High value - worth decoding

18 · WORLDMAP_GEOGRAPHY — #1 priority

Geography giving worldmap areas their real extent/anchor. Finishes the in-flight map-label feature: 877 named areas are decoded but not placed, because AREA carries no polygon. Unblocks a feature already half-built.

2 / 34 · STRUCT

Param-bag records; most modern content metadata (item variants, minigame, diary/collection-log config) lives here. Cheap - rides ingest_definitions.

2 / 8 · ENUM

id → id / id → value tables the client dereferences everywhere. Resolves many "what does this id map to" joins. Cheap, additive.

2 / 16,19,15 · VAR*

VARPLAYER + VARCLIENT + VARCLIENTSTRING complete the var system started with VARBIT(14). Needed to interpret player state references end to end.

2 / 38,39 + 21 · DB tables

DBROW + DBTABLE + DBTABLEINDEX - Jagex's newer relational data tables (a lot of post-2021 content). Decode all three together.

Medium

2 / 12 · SEQUENCE

Animation metadata (frame ids, durations). Useful only if animation ever matters; no current 2D use.

24 · GAMEVALS

Internal symbolic names for ids. Could enrich admin/debug tooling (human-readable ids); not user-facing.

Low / skip unless a feature demands it

0 ANIMATIONS, 1 SKELETONS, 22 ANIMAYAS - only for animated 3D previews; icon render is static-pose.
3 INTERFACES - widget layouts; large, complex; no current use.
4, 6, 11, 14, 15 - all audio; novelty only for a clan web platform.
10 BINARY - misc; huffman only relevant to chat decoding (out of scope).
12 CLIENTSCRIPT - CS2 bytecode; high-effort RE; overkill.
13 FONTS - authentic RS glyphs; web-app already uses font-rs-* webfonts.
20 WORLDMAP_GROUND - base imagery; service renders its own tiles from archive 5, so redundant.
2 / 3,5,11,13,32,33 - narrow support/visual defs; no clear project use.

How a decoder would be added

Config groups (8/16/34/38/39): additive, no ingest.py change - new app/definitions/<type>.py, DB model + migration, one registry.py entry.

Whole archives (18/20/21): new ingest_<archive>.py + models + wiring in app/services/ingest.py _ingest_build, following ingest_worldmap.py.

Validation: captured real-group fixture under tests/fixtures/ + a full-build pass (0 failures, ids matching the OSRS Wiki).
