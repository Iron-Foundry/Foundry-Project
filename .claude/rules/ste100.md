# STE100

> PAG (Pattern Abstract Grammar) is Bane's Lab IP, used under CC BY-SA.

THIS POLICY ENFORCES that every sentence a session emits - a reply, a docstring, a comment, a changelog line, a memory file, a commit message - is ASD-STE100 Simplified Technical English.

%% META %%:
    intent: "One register for every sentence, so a reader gets the fact and never the style"
    objective: "No sentence ships with two topics, a past tense, a metaphor, or more than 25 words"
    context: "The operator set STE100 as the register of every sentence. It outranks every terseness rule: the article stays"
    criteria: "Every sentence you write passes PHASE 4 before you send it or save it"
    priority: AXIOM
    trust: counted_words = TRUSTED, "it reads well" = UNTRUSTED

DECLARE procedural_max: number
DECLARE descriptive_max: number

SET procedural_max = 20
SET descriptive_max = 25

# PHASE 1: THE SENTENCE
    @purpose: "One topic, one clause, one verb the reader can act on"

    RULE one_topic_per_sentence:
        ALWAYS WRITE one topic IN one sentence
        NEVER JOIN a second topic WITH a semicolon, a colon, a dash, "and", or "which"
        WHEN two facts are related:
            WRITE two sentences
        # a semicolon is the most common way this register fails

    RULE present_tense_active_voice:
        ALWAYS WRITE what the code DOES, IN the present tense
        NEVER WRITE what the code USED to do, what it "had", or what "was" wrong before
        NEVER WRITE the passive voice WHERE an actor exists
        # this is `overwrite_dont_annotate` at sentence level: history belongs in version control

    RULE count_the_words:
        KEEP an instruction UNDER procedural_max words
        KEEP a description UNDER descriptive_max words
        WHEN a sentence is longer:
            SPLIT it AT the conjunction

    RULE keep_the_articles:
        ALWAYS KEEP `the` and `a`
        NEVER DROP an article FOR brevity
        # brevity is a word count, never a dropped article

    RULE one_instruction_per_step:
        WRITE one action IN one numbered step OR one bullet
        NEVER PUT a condition AND an action IN the same clause chain

    VALIDATION GATE:
        ✅ no semicolon joining two topics
        ✅ every verb is present tense and active
        ✅ every sentence counted and under its bound
        ✅ every article kept

# PHASE 2: THE WORDS
    @purpose: "One approved word, one meaning, no picture the reader must decode"

    RULE no_metaphor_and_no_personification:
        NEVER WRITE that code "reads as", "tells", "says", "lies", "knows", "wants", or "is a leaf"
        NEVER DESCRIBE a surface BY what it resembles
        ALWAYS STATE the mechanism OR the result
        # "a block that cannot be moved is a control that lies" -> "an owner cannot move this block"

    RULE one_meaning_per_word:
        ALWAYS USE one word FOR one thing ACROSS the whole repository
        NEVER SWAP a synonym FOR variety
        # a clip is a clip in every file, never a "motion file" in one and a "video" in the next

    RULE no_gerund_string_and_no_noun_cluster:
        NEVER CHAIN two gerunds ("stopping cropping", "for deciding whether")
        NEVER BUILD a noun cluster OVER three words
        REWRITE it AS a verb WITH its object

    RULE no_hedge_and_no_filler:
        NEVER WRITE "just", "simply", "basically", "actually", "essentially", "of course",
            "happens to", "arguably", "somewhat", "fairly"
        NEVER OPEN a reply WITH "Sure", "Certainly", "Great question", or a restated question

    RULE no_rhetoric:
        NEVER WRITE a contrast pair ("not X, but Y") WHERE Y alone is the fact
        NEVER WRITE a rhetorical question
        NEVER WRITE a sentence whose job is emphasis
        # `no_em_dashes` in `.claude/rules/wording.md` bans the punctuation this habit reaches for

    VALIDATION GATE:
        ✅ no metaphor, no personified code
        ✅ one term per concept
        ✅ no gerund chain, no four-word noun cluster
        ✅ no hedge, no filler, no rhetorical pair

# PHASE 3: SCOPE
    @purpose: "What the register covers, and the four things it does not touch"

    | Covered | Not covered |
    |---|---|
    | every reply to the operator | a code identifier (the rule below) |
    | every docstring and comment you write | a quoted error message |
    | changelogs | a code block |
    | `CLAUDE.md`, `.claude/rules/*`, `.claude/reference/*`, the harness memory store | a third party's own words |
    | every commit message and PR body | |
    | copy that ships on a surface | |

    RULE an_identifier_is_not_a_sentence:
        # an identifier is exempt from PHASE 1 and PHASE 2 because it obeys this instead
        ALWAYS NAME a thing WITH a domain noun phrase, OR a verb PLUS its object:
            `grantRole`, `revokeRole`, `pendingOwnerGrant`, `OWNER_GRANT_WARNING`
        ALWAYS TAKE the noun FROM the schema, the table, or the wire
        NEVER WRITE an identifier AS a sentence:
            `putSomebodyInAPlace`, `takeSomebodysPlaceAway`, `raiseTheAskedOwner`
        NEVER WRITE a bare verb: `write`, `give`, `submit`
        NEVER SPEND a word the repository already spends ON something else

    RULE edited_prose_obeys_it:
        WHEN you write OR edit a sentence:
            APPLY this policy TO that sentence
        NEVER OPEN a bulk pass OVER prose you are not otherwise touching
        # same shape as `inherited_breaches_split_on_contact` in `.claude/rules/code-shape.md`

    RULE the_repo_holds_older_prose:
        NEVER COPY the register OF a docstring you are reading
        # older prose predates the rule; an old sentence is not a licence

    VALIDATION GATE:
        ✅ every sentence in the diff obeys it
        ✅ every identifier in the diff is a noun phrase or a verb plus its object
        ✅ no untouched file rewritten for register alone

# PHASE 4: VERIFICATION
    @purpose: "Check the sentence before it is sent, not after the operator reads it"

    STEP 1:
        FOR EACH sentence you are about to send or save:
            COUNT its words AGAINST its bound
    STEP 2:
        SCAN it FOR `;`, "which", "used to", "was", "would have", "reads as", "just", "simply"
        IF a hit: REWRITE the sentence
    STEP 3:
        NAME the sentence's one topic
        IF you name two: SPLIT it
    STEP 4:
        NAME the verb
        IF it is passive OR past tense: REWRITE it

    VALIDATION GATE:
        ✅ steps 1-4 run on every sentence, including this reply

ALWAYS:
    - NAME a thing with a domain noun phrase, never with a sentence
    - WRITE one topic per sentence, in the present tense, in the active voice
    - KEEP the articles
    - STATE the mechanism instead of a picture of it
    - USE one word for one thing
    - CHECK the sentence before you send it

NEVER:
    - JOIN two topics with a semicolon, a colon or a dash
    - NARRATE what the code used to do
    - PERSONIFY code, or describe a surface by what it resembles
    - CHAIN gerunds, or build a noun cluster over three words
    - WRITE a hedge, a filler word, or a sentence that only adds emphasis
    - REWRITE untouched prose to fix its register
