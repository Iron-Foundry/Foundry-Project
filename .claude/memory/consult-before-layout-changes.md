name: consult-before-layout-changes
description: Present a plan and get approval before editing any layout or design code
metadata:
  type: feedback
---

Do NOT edit layout or design code (component structure, responsive breakpoints, spacing, Tailwind classes, visual styling) on your own initiative. Present the plan first and get explicit approval, then make the changes.

**Why:** The user owns layout/design decisions and rejects unapproved visual changes; a diagnosis is not a license to edit.

**How to apply:** For any task touching layouts or designs, investigate and diagnose freely, then lay out the proposed change and wait for a go-ahead before touching files. Non-visual code changes do not require this. Relates to [[no-git-on-own-initiative]].
